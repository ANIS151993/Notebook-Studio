A Practical Framework for Serverless CSV Intelligence with Interactive Notebook Automation and Local AI Runtime Repair

Author: MD ANISUR RAHMAN CHOWDHURY

Affiliation: Gannon University

Application URL: https://datamentor.marcbd.site

Abstract

This research presents a production-deployed, serverless data engineering platform, Notebook Studio, designed to convert raw CSV exports into cleaned datasets, reproducible Python notebooks, and interpretable analytics outputs. The platform integrates browser-executed Python, cloud identity and workspace persistence, resilient local fallback, and a hybrid local AI repair layer for execution-time debugging. The central hypothesis is that a guided, automation-first architecture can reduce preprocessing burden, increase reproducibility, and improve runtime error recovery for both educational and operational analytics contexts [1]-[8].

1. Introduction

Real-world CSV inputs often contain inconsistent headers, whitespace noise, duplicate rows, sparse records, and ambiguous types. Manual correction is slow and non-reproducible. Existing workflows frequently split across multiple tools, which weakens traceability and increases onboarding cost. Notebook Studio was built to unify cleaning, notebook execution, visualization, and account continuity in one web interface.

2. Research Objectives

  1. Design a browser-accessible pipeline for deterministic CSV cleaning and notebook generation.
  2. Evaluate time-efficiency against manual baseline preprocessing workflows.
  3. Measure reliability of runtime error recovery under automatic repair strategies.
  4. Assess usability for real-world contexts: education, SME operations, and analyst pipelines.

3. Research Questions

  1. Can serverless browser-native execution support practical, repeatable data cleaning workflows?
  2. What measurable productivity gains are achieved versus manual preprocessing?
  3. How effectively can hybrid rule-based + local-model repair reduce notebook runtime failures?

4. System Architecture Summary

  • Data Intake Layer: CSV ingestion, schema normalization, deduplication.
  • Notebook Layer: guided code cells for transparent cleaning logic.
  • Execution Layer: in-browser Python runtime with deterministic outputs.
  • Persistence Layer: cloud workspace + local fallback continuity.
  • Intelligence Layer: automatic runtime repair loop (rules first, local neural fallback).
  • Analytics Layer: standard and custom visual diagnostics for quality and performance.

5. Methodology (Line-by-Line Experimental Procedure)

  1. Collect heterogeneous CSV samples from academic and operational contexts.
  2. Execute baseline manual preprocessing and log time per workflow stage.
  3. Run identical datasets through Notebook Studio automated cleaning pipeline.
  4. Generate notebook artifacts and execute cells in-browser under controlled order.
  5. Inject representative Python errors (syntax, NameError, KeyError, indentation, incomplete calls).
  6. Observe runtime recovery behavior: rule-based repair, neural fallback, retry count, terminal status.
  7. Capture outcome metrics: total time, fix success, unresolved cases, user continuity status.
  8. Compare baseline vs automated outcomes using line, bar, radar, and scatter analytics.

6. Evaluation Metrics

Metric Definition Target Outcome
Workflow Time End-to-end minutes from upload to validated notebook output Lower than manual baseline
Repair Latency Time from runtime error detection to stable execution Reduced via auto-repair loop
Reproducibility Ability to rerun the same pipeline with equivalent outputs Consistent notebook/state behavior
User Continuity Recovery of work across sessions/cloud interruptions No material workflow loss

7. Results and Discussion

Observed outcomes indicate substantial reduction in preprocessing effort and improved operational transparency. The system consistently reduced repetitive cleanup overhead and accelerated issue resolution when compared with manual notebook-only workflows. While not all arbitrary logic errors are automatically solvable, the hybrid repair strategy improved first-pass recovery rates and reduced debugging fatigue.

8. Real-World Use Cases

  • Academic Labs: reproducible student workflows for data cleaning and notebook literacy.
  • SME Operations: low-friction preprocessing for teams without dedicated data engineering.
  • Analyst Teams: fast readiness checks before model training, anomaly, or fraud analysis.

9. Limitations

  • No automated repair framework can guarantee universal correction for all Python logic defects.
  • Complex semantic/business-rule bugs still require human validation.
  • Local model quality depends on runtime availability and browser capability.

10. Conclusion

Notebook Studio demonstrates that a serverless, user-centered architecture can deliver practical and sustainable data preparation intelligence with measurable productivity gains. The combination of deterministic processing, interactive notebooks, resilient persistence, and hybrid local AI repair creates a strong foundation for applied analytics in both education and professional operations.
